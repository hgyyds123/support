什么是 Supabase 反向代理？

hg 站点的账号、社区和聊天室数据存放在 Supabase 上。为了让访问更稳定、更快，站点在用户与 Supabase 之间加了一层反向代理，由它代为转发请求。

您的浏览器 → hg 反向代理 → Supabase 服务

这层代理依托分布在全球的边缘网络（Wasmer）运行，目的是让国内访问也能以较短路径直连数据库与 AI 服务，而不必绕远路。

反向代理做了什么

  • 统一入口：浏览器只需要连接 hg 域名，不必直接指向数据库地址，减少暴露面。
  • 转发与缓存：请求由代理转发到后端服务，部分静态与重复请求可被缓存，从而加快响应。
  • 缓冲与容错：后端短暂抖动时，代理可以先兜住请求，降低页面直接报错的概率。
  • 简化配置：更换后端地址时无需改动前端代码，对使用者完全透明。

作为使用者，您不需要配置任何代理参数，正常使用即可。这一层完全由站点维护。

代理出问题时会怎样

如果代理链路不稳定，页面会表现出下面这些症状：

  • 提示「网络连接失败」或请求长时间无响应。
  • 页面加载到一半停住，聊天室消息迟迟不刷新。
  • 登录时提示 400 或 500，或频繁要求重新登录。
  • 图片等资源加载缓慢或反复失败。

遇到这些情况，请先按 网络连接失败或代理超时怎么办？ 排查，再参考 400 Bad Request 排查 与 服务器内部错误 (500) 修复进度。如果确认是代理链路问题，请通过 邮件联系站长 反馈出现时间。

为什么聊天室看起来"慢半拍"

聊天室并非通过长连接实时推送，而是在代理之后按一定间隔拉取新消息，因此会有轻微的延迟。关于这一点以及它带来的影响，见 为什么聊天室没有使用 WebSocket？。

了解代理的作用后，遇到网络问题时就更容易判断问题出在哪一段链路上了。
